# Label Studio 局域网直连设计

## 目标

消除浏览器加载大量三视角图片时，单条 SSH TCP 会话产生的队头阻塞和超时，同时继续使用 Dell 上现有的 Label Studio Project 2、SQLite 数据库和本地媒体根目录。

## 已确认事实

- 本机地址为 `192.168.105.67`，Dell 地址为 `192.168.105.166`，两端均通过 Wi-Fi 接入同一局域网。
- Dell 上 Label Studio 当前监听 `127.0.0.1:8081`，数据库目录为 `/home/dell/datasets/robointer_triview_labelstudio/label-studio-data`。
- 媒体根必须保持 `/home/dell/datasets/robointer_triview_1000`，并启用本地文件服务。
- Dell 直接访问 Label Studio 通常为 11–16 ms；经真实 18082 隧道并发访问会出现 5–8 秒超时。

## 方案比较

1. **局域网直连并限制来源（采用）**：Label Studio 绑定 `192.168.105.166:8081`，防火墙仅允许 `192.168.105.67/32` 访问。浏览器直接访问 Dell。它移除 SSH 加密和单连接复用，改动最小、性能最好。
2. **局域网直连加本机用户态代理**：可保留 `127.0.0.1:18082` 和现有 Cookie，但本机没有现成代理工具，需要新增常驻进程，故暂不采用。
3. **多条 SSH 加负载均衡代理**：需要多个隧道和额外代理，而且全部仍共享同一 Wi-Fi 链路，复杂度最高，故不采用。

## 实施设计

1. 读取现有防火墙状态；若 UFW 已启用，则添加仅允许本机访问 8081 的规则。若 UFW 未启用，则只添加针对 8081 的临时 iptables 规则，不改变系统默认策略或 SSH 规则。
2. 精确停止当前 Label Studio PID，并以相同数据目录、legacy API token 和本地媒体环境变量重新启动，仅把 `--internal-host` 改为 `192.168.105.166`。
3. 从 Dell 本机和 Windows 本机分别验证 Project 2 页面返回 200 或 302，并连续请求以确认无超时。
4. 直连验证通过后，只停止当前 18082 Plink 进程；不创建 watchdog、计划任务或自启动脚本。

## 安全与回滚

- 防火墙规则仅涉及 TCP 8081，不改变 22、默认策略或其他服务。
- 启动失败、远端健康检查失败或本机直连失败时，立即恢复 Label Studio 到 `127.0.0.1:8081`，并保留现有 18082 隧道。
- 任何步骤都不修改 Project 2 数据、SQLite 内容、任务、预测或标注。

## 验收标准

- `192.168.105.166:8081` 仅由 `192.168.105.67` 访问。
- Project 2 页面连续 10 次请求无超时，返回 200 或 302。
- Label Studio 使用原数据库和媒体根；Project 2 仍为 1200 个 task。
- 18082 的 Plink 进程在直连验证成功后关闭，watchdog 和计划任务仍不存在。

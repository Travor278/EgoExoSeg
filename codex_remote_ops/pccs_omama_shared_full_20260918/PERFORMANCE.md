# GPU利用率诊断（进行中）

显存占用不代表GPU计算利用率。此前报告的7.902GiB是PyTorch峰值分配量，不能作为GPU充分利用的证据。

平台GetTaskMetric实际读数：稳定进入全量附近的一分钟节点聚合GPU利用率约17.5%～35.25%，CPU使用率约0.050（按80个申请核折算约4核）。API证据见utilization_snapshot.json，包含启动阶段，不能据短窗口推断整个运行的平均。

在当前作业容器中用只读nvidia-smi和/proc采样41.05秒、9次：

| GPU | 采样平均利用率 | 最小～最大 |
|---|---:|---:|
| 0 | 46.33% | 1～100% |
| 1 | 26.44% | 1～98% |
| 2 | 17.11% | 1～77% |
| 3 | 27.33% | 1～75% |

四个worker进程CPU时间分别相当于单核的99.95%、99.90%、99.92%、99.92%。GPU呈突发计算，CPU串行路径和同步开销是明确的排查方向；尚不能仅凭CPU100%将CUDA等待排除。证据perf/system_sample.json。

静态代码中可疑开销：dataloader num_workers=0；同一批候选先原PCCS再3次完整PCCSMetric.process；每对象重复对整批预测做signature并搬回CPU；DINO统计中多次float(tensor)引发设备同步。这些是待测瓶颈，不把静态推测当耗时占比。

profile_worker.py仅在已有节点GPU0对前16pairs运行隔离cProfile，所有输出放perf/profile_baseline，最多600秒。主实验源码、maskbank和记录不修改。采样包括模型初始化且与主任务共享GPU，不作为无干扰吞吐基准。后续依据函数耗时，优先研究候选指标只算一次/复用、hash按batch缓存、CPU预处理预取，再验证选择与指标一致；尚未将优化部署到主实验。

用户随后要求不再继续利用率优化，正常运行时恢复0.8×ETA监督。已终止任务专属Web终端中的临时前台函数profiler，未修改或停止两个主实验。当前仅保留上述41秒只读采样作为诊断证据，不宣称函数级瓶颈或提速已验证。
